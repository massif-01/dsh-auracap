## 2. 本次检查发现的衔接问题

| 问题 | 当前证据 | 统一处理 |
| --- | --- | --- |
| 新旧样式并存 | 设置主体仍是 16px 圆角和横线分隔，新增备份区却是 20px 分组框、12px 按钮 | 设置主体整体采用已确认的分组方案，备份是同级分组 |
| 小标题颜色不一致 | `.ac-sec-label` 使用 secondary；记忆、用量标题使用 primary；备份标题单独写死灰色 | 按文字角色统一，说明性小标题使用宿主 tertiary，浅色对应 `#81858c` |
| 未连接状态缺少本地设置 | `SettingsModal` 只有连接后才创建记忆、用量等区域，未连接时主要是授权与备份 | 本地内容设置始终可用；连接状态只控制手机相关内容 |
| 首次进入缺少直接恢复入口 | 引导只有连接手机和电脑导入；恢复藏在设置里 | 在欢迎页加入低权重文字入口，复用现有恢复流程 |
| 引导仍是原有展示 | 当前 `Onboarding` 尚未使用已确认的四态布局和清楚的安装说明 | 按四态方案迁移，绑定真实状态，不把演示推进按钮当作业务完成 |
| 旧预览备份语义过时 | 静态菜单仍写“仅导出原图”“张原图”，恢复确认未说明用量清零等现行规则 | 使用“图片”；文案以现行功能为准 |
| 预览交互没有全部进入正式代码 | 设置焦点限制、原生分组主要由预览脚本补上；正式设置容器没有对应 dialog 语义 | 把必要语义与焦点行为落实在正式组件中 |
| 旧构建会混入新功能 | `components()` 默认读当前 `client.js`；旧备份预览又在用量后注入演示 BackupPanel，而当前 SettingsModal 已含真实 BackupPanel | 旧产物冻结；新一轮预览明确源码版本和服务边界，不能直接重跑旧脚本覆盖 |

另外发现一个真实交互缺口：引导预览的“返回”只是切换演示页，正式接口目前没有单独取消一次待授权流程的操作。恢复又会拒绝尚未完成的授权。现已确认“返回”须结束本次未完成授权，具体语义见第 7 节，不能照搬仅切换页面的演示行为。

## 3. 统一视觉规则

### 颜色和文字

| 角色 | 浅色视觉参考 | 使用范围 |
| --- | --- | --- |
| 正文与正式标题 | `#0f1115` | 内容标题、正文、弹窗标题、菜单动作名称 |
| 说明文字 | `#61666b` | 功能说明、步骤描述、非关键状态 |
| 小标题与辅助信息 | `#81858c` | 核心内容、行动项、待确认、标签、线索；设置分组和子组标题；步骤提示、时间等 |
| 页面和面板 | 白色 | 主内容、设置、菜单、恢复窗口 |
| 内部状态底面 | `#f6f7f8` 附近的宿主层级色 | 同步状态、配置详情、恢复替换说明、处理进度 |
| 轮廓 | 黑色低透明度 | 分组外框约 `.5px / #00000029`；主要区域分隔更轻 |

“灰色小标题”指引导读者理解结构的标签，不是把正文、菜单操作和按钮全部变灰。不能因为某块内容重要，就把“行动项”等标签改成黑色。

生产实现优先使用宿主现有语义变量；上述十六进制值是已确认浅色外观的对照值，不把整套宿主颜色重定义在 `html` 上。保持现有字体栈和宿主字体优先级，不新增字体。此次视觉验收以已确认浅色方案为准，保留宿主已有主题能力，不另做一套深色设计。

### 尺度和层次

- 主界面头部、标签栏、列表与详情的几何布局保持。列表宽度沿用当前 236px / 窄窗口 208px 的规则。
- 设置保留现有最大 820px 单列宽度、约 88vh 高度和一个主滚动容器；增加备份后允许自然滚动，不压缩所有块来强塞一屏。
- 设置外面板 28px；同级功能分组 20px；恢复窗口沿用已确认的 24px；菜单和较大输入区 16px；常用按钮与内部状态底面 12px；小图标交互区 8px。
- 同级分组间距主要用 16–24px；同组内部用 12–24px 留白。内部关系不再用横线逐行切割。
- 保留主界面的必要区域边界，如列表与详情边界。细线表达真实边界，不机械删除全部边框。
- 对齐、留白和底面承担层级；不增加装饰徽章、编号、渐变或自动入场动画。编号只用于真实步骤。

## 5. 设置弹窗

连接状态信息保留在顶部，内容依次为：

```text
AuraCap 设置                                      关闭
连接状态 / 仓库 / 立即同步或连接操作

记忆                     同级功能框
  项目上下文             编辑与保存
  Agent 访问             说明 + 开关
  索引                   摘要 + 展开动作

用量                     同级功能框
  数字 / 模型 / 费用与统计说明

备份与导出               同级功能框
  说明
  [导出 ▾]  [从备份恢复]
  范围说明 / 最近导出时间 / 当前任务状态

高级设置                 可展开
```

记忆、用量、备份三个框使用同一边框、圆角、标题色与内边距。备份不能看起来像后贴上的独立产品。“记忆”组内部去掉项目上下文、Agent 和索引之间的硬横线；用量保留数字主次，但不因新增备份而挤小字体。

**已确认的未连接状态：**记忆、用量、备份仍显示，分别呈现实际内容或空态；顶部保留唯一的连接操作，手机展开区说明后续步骤，不重复摆第二个连接按钮。已连接设备才有的同步或配置操作不显示成可用。不会为了从备份恢复，要求用户先连接 GitHub。此项改变的是设置的可见条件，不新增后端内容功能。

### “把手机接进来”展开

展开后是一整个 20px 圆角功能框，内部依次为：

1. 灰色“连接步骤”。下载快捷指令、传到 iPhone 安装、发送测试图（可选）依原顺序排列；每步标题、解释、动作靠近，步骤之间留白。
2. 灰色“同步状态”。待处理、上次同步、必要时上次尝试，放在一个 12px 浅灰底面内，数值右对齐；同步频率说明放在该底面内部。

首次引导中的“发送第一张图片”和设置中的“发送测试图（可选）”保留各自用途，不能为了统一字面而混成同一个动作。

### “高级设置”展开

同样使用完整功能框，内部只有两个清楚的区域：

- 灰色“连接诊断”：检查连接、显示调试配置；展开的配置详情放入浅灰底面，显示/隐藏和复制动作属于此底面。
- 灰色“连接管理”：断开连接及其解释，使用更大的组间留白；危险色只用于断开操作及其确认，不染红整个区域。

展开标题、内部小标题不因展开就突然变成一串黑色加粗文字。展开箭头、`aria-expanded` 与内容显隐一致。

## 6. 备份与恢复在新界面中的规则

### 导出

保留已确认的三项菜单及顺序：

| 菜单名称 | 说明要点 | 格式 |
| --- | --- | --- |
| 导出整个包 | 图片、文本、已有总结与洞察、分组，可完整恢复 | `.auracap.zip` |
| 仅导出图片 | 保存当前可用的图片，保留现有文件格式 | `.zip` |
| 仅导出文本内容 | 片刻、文档文字、日洞察、周迹、月迹、岁迹及项目上下文 | Markdown ZIP |

不再承诺“最初原图”“无损还原最初文件”。完整包不包含原始 PDF、密钥和源设备运行状态；不把这些内部规则全部塞进菜单副说明，恢复确认中说明与用户决策相关的结果即可。

菜单保留约 420px 宽度，以动作区域可用宽度为上限；沿已确认的向上展开方式处理，空间不足时调整方向，不能被设置滚动区截断。窄窗口可简化右侧格式标记，但必须保留三项用途的区别。键盘方向键、Home/End、Escape、Tab 及回焦保留。

导出状态放在备份组内：等待、整理、打包、文件已准备好。提供实际下载链接。“文件已准备好”不写成“已保存到电脑”。最近记录继续叫“最近导出完整备份”，只由实际传输结果更新，不以菜单点击更新。

### 恢复

设置和欢迎页入口使用同一个恢复窗口、同一份任务状态，不创建两套上传、检查、确认逻辑。保留已确认的文件选择区、文件与时间、三组数量、替换说明和右下角操作构成。

确认文字必须准确表达：

> 当前内容将被完整替换。已有总结与洞察直接恢复，不合并、不重新调用模型。设备连接与权限设置保留，用量记录清零。

不把“图片/文本单独导出包”呈现成可恢复包；检查失败明确让用户重新选择完整备份。

| 真实阶段 | 展示与操作 |
| --- | --- |
| 选择文件 | 选择备份文件、取消 |
| 上传、检查、检查完成、等待当前任务完成 | 展示实际阶段；允许的阶段提供取消；检查完成显示“重新选择 / 恢复此备份” |
| 准备图片和内容、目录切换、提交载入、回滚 | 展示实际状态；不提供后台不支持的取消或第二次确认 |
| 成功 | “恢复完成”，展示真实数量，按钮“完成” |
| 失败且原库确认可用 | 说明未替换或已返回原内容，并提供明确下一步 |
| 已提交但需要重新载入 / 恢复状态待处理 | 明确需要重启插件或检查状态；不写“恢复完成”，不诱导再覆盖一次 |
| 任务过期、查询失败 | 过期可重新选择；查询失败可“重新检查状态”，不能困在一直禁用的窗口里 |

进度只显示已有真实数据，不模拟百分比或倒计时。关闭设置不等于取消后台导出；重新进入后接回实际任务，不能因组件重挂载自动重复下载。

## 7. 首次进入和四个引导状态

保留已确认的左右两栏：左侧说明当前任务和主要动作，右侧承载流程、验证码或安装步骤。欢迎页不用品牌标语充当主要操作说明；原有标语保留为低权重文字。小标题灰色，步骤与状态区分清楚。

| 主状态 | 左侧 | 右侧 | 状态依据 |
| --- | --- | --- | --- |
| 首次进入 | “从第一条片刻开始”；连接手机为主按钮，从电脑导入为次按钮 | 手机 → 私有仓库 → 这台 Mac 的简明说明 | 没有可展示内容，且没有进行中的手机设置步骤 |
| GitHub 授权，1/3 | “连接 GitHub 中转”；打开 GitHub 授权；返回结束本次未完成连接；保留电脑导入 | 复制验证码 → 输入并授权；等待或准备中转状态 | 待授权与 provisioning 的真实状态，不能只靠点击推进 |
| 安装快捷指令，2/3 | 明确 GitHub 已连接，但手机还没有被确认安装；下载快捷指令 | 下载到 Mac → AirDrop 安装 → 从相册分享第一张图片 | GitHub 连接成功；尚未发起本次下载 |
| 等待第一张图片，3/3 | “等待第一张图片”；检查是否收到、重新下载、先从电脑导入 | 保留完整安装和首次发送步骤 | 已发起下载，不等于手机安装成功；实际收到内容才退出等待 |

现行快捷指令下载逻辑只能确认已取得文件并发起浏览器下载，因此提示使用“已发起快捷指令下载，请在 Mac 确认文件后传到 iPhone”，不把它写成可验证的手机安装成功。拒绝授权、过期、复制失败、下载失败或同步失败，使用原状态中的就近说明和重试，不新增一排页面或全局成功浮层。

**已确认的恢复入口：**欢迎页两个按钮下方增加“已有备份？从备份恢复”文字入口。它不是第三个主按钮，不新增一张卡片，不改左右两栏；点击直接打开共享恢复窗口。之后的三个手机步骤不重复铺设恢复入口，设置中的恢复仍可到达。

**已确认的“返回”语义：**结束这次尚未完成的连接过程，回到欢迎页；之后可直接恢复备份，想连接时再点“连接手机”重新开始。已经连接好的设备不受影响。

实施时为当前未完成授权提供最小的独立取消操作。不能借用“断开连接”，也不能只 `setDevice(null)` 隐藏页面。取消得到确认后再完成返回；该流程的旧轮询和迟到响应不能继续推进界面或提交连接状态。取消失败时就近说明并允许重试，不显示已经结束。这里只处理本次连接流程，不重写授权系统。

已有内容的用户无需重走四步引导。恢复在未连接设备上成功后也直接展示恢复内容；连接手机是可后续完成的设置。

## 8. 窗口、焦点与状态一致性

- 设置、恢复及其他已有弹窗采用一致的面板、遮罩和关闭习惯；恢复在最上层时只由它接收焦点，底层设置暂不可交互，避免双重模糊及遮罩不断加深。
- 正式设置补上 dialog 名称、焦点进入/限制/返回。恢复窗口关闭回原入口；引导任务推进后焦点进入新标题。预览里已做到的行为不能遗留在演示脚本中。
- 菜单 Escape 只关闭菜单；恢复 Escape 只处理恢复；只有允许关闭的阶段才关闭，不能同时把底层设置关掉。
- 视觉对照切换保留项目上下文草稿和展开状态；普通展开折叠、选择或检查备份、取消未提交恢复也不清空编辑内容。
- 真正发生内容库代次变化时，继续采用现有统一重载：丢弃旧库草稿、旧详情和搜索结果，保留允许保留的视图偏好和任务状态。成功恢复或回滚重载不能被“保留预览草稿”的规则覆盖。
- 组件样式统一不改变库代次校验、恢复事务、附件重建或“不调用模型”的业务承诺。
- 引导按插件容器宽度适配：约 900px 开始收紧留白，约 680px 以下按已确认方案单列，任务说明在前。设置和菜单以实际可用区域适配，不能只按整个 Harness 窗口宽度判断。
- 检查长文件名、长仓库名、长中文、空值及按钮换行；文字不被裁成不可识别的操作，关闭和确认可达。保留减少动效规则。

## 9. 实施收敛方式与预览交付

1. 以当前代码作为功能基线，先记录版本与哈希。旧预览作为视觉参考冻结，不反向覆盖当前 `client.js`。
2. 在现有 CSS 中合并颜色角色、按钮和弹窗尺度，修改实际所属规则；删除被替代的旧规则，避免在文件末尾不断追加互相抵消的覆盖。
3. 直接整理正式设置的语义分组，保留现有编辑器、回调和任务；不把预览的 React 元素树遍历/按 class 注入分组方式带进生产。
4. 保留现有备份服务和库切换入口。欢迎与设置复用恢复任务和呈现，仅调整必要的 UI 状态归属，不新建通用弹窗框架或备份状态机。
5. 迁移四态引导至现有组件，按真实服务结果推进；落实已确认的“返回结束本次未完成授权”，将最小取消操作作为单独小项说明和验证。
6. 新预览从同一个明确的当前源码快照和同一份示例数据生成：正式外观作为对照，融合外观作为候选。演示服务必须显式提供，不通过请求失败后填空数据兜底；备份区只出现一次。
7. 继续保留既有五项修复：脚本数据转义、原版/新版对照隔离、草稿与展开状态保留、标题焦点、本地固定依赖及校验。旧的“五项通过”只证明当时的静态预览，不自动证明本次新版本通过。

准备实施时的交付顺序：先补齐统一静态预览并审视，再迁移正式 UI，最后做对应范围的真实组件与业务接口回归；不一边换视觉方向一边修改恢复业务。

## 11. 已确认的补充决策

以下三项均于 2026-11-11 经用户确认，纳入固定版 v1.0 的实施与验收范围。

| 补充 | 固定决策 | 原因 |
| --- | --- | --- |
| 欢迎页直接恢复 | 增加低权重文字入口 | 换机用户可先恢复，不必先授权手机或寻找设置 |
| 未连接时的本地设置 | 记忆、用量、备份照常显示 | 本地内容和恢复能力不应依赖 GitHub 连接 |
| 授权中的“返回” | 结束本次未完成连接后返回欢迎页；再次连接重新开始，已有连接不受影响；落实最小取消服务配套 | 防止视觉上退出、后台仍授权并阻塞恢复 |

这三项是在此前预览基础上、本次重新审查后追加并确认的决策。后续按本文实施，不再保留仅隐藏授权页的替代方案。其余按已确认方向收敛，不另行扩大功能范围。
