## Bug 与状态缺陷

### R01 重复重连后，返回仍留下隐藏授权

位置：[重连入口](/Users/massif/dsh-auracap/client.js:2792)、[发起连接](/Users/massif/dsh-auracap/client.js:3450)、[取消当前连接](/Users/massif/dsh-auracap/client.js:3464)、[创建授权流程](/Users/massif/dsh-auracap/index.js:1356)。

**复现：**模拟已有连接需要重新授权，在设置点击“重新连接 GitHub”；验证码出现后，该重连按钮仍可再次点击。第二次发起后点“返回”。界面已经没有授权面板，但第一次流程仍为 `pending`，第二次为 `cancelled`；真实恢复确认接口返回 `409 BUSY`，要求完成或取消手机连接。

**根因：**前端只记住最新一个 `device.id`，后端保留多个流程；新增取消接口只取消指定流程。单流程测试通过，并不意味着界面能管理已经发起的全部流程。

**收敛方向：**一个界面拥有一个明确的未完成连接流程。再次发起时应复用或明确替换旧流程，并同步处理旧流程的生命周期；不应要求用户寻找已经不可见的授权。

证据：[浏览器记录](/Users/massif/dsh-auracap/output/ui-full-review-20261111/browser-findings.json)、[返回后的界面](/Users/massif/dsh-auracap/output/ui-full-review-20261111/hidden-authorization.png)。GitHub 连接状态为模拟，取消与恢复准入使用真实接口。

### R02 授权写入时卸载插件，会留下账号不一致的连接

位置：[写入凭据与发布连接](/Users/massif/dsh-auracap/index.js:1434)、[卸载处理](/Users/massif/dsh-auracap/index.js:3239)。

**复现：**已有账号 A；用账号 B 重新授权，在凭据服务的写入等待期间卸载插件，然后让该写入完成。隔离生命周期复现的结果是：凭据账号为 B，`state.json` 的仓库账号仍为 A。

**根因：**凭据提交与连接元数据落盘分两步；卸载先增加 `flowGeneration`。凭据服务完成写入后，流程在代次检查处返回，未完成连接元数据的提交。运行中的 `flow.committing` 保护只让调用者等待，无法让两份持久化状态保持一致。

**影响：**重新加载后可能拿新账号的凭据访问旧账号仓库，连接看起来存在，同步或快捷指令却失败。这不是本轮证实的数据丢失，也不是本次才出现的风险。

**收敛方向：**把授权本地提交的生命周期定义完整；卸载应等待一个一致的提交结果，或保留可确定恢复的提交信息，不能在凭据已写后只跳过另一半。

证据：[独立复现脚本](/Users/massif/dsh-auracap/output/ui-full-review-20261111/auth-unload.mjs)。脚本仅使用虚构凭据。

### R03 迟到配置会覆盖刚输入的草稿

位置：[项目上下文初始化](/Users/massif/dsh-auracap/client.js:2567)、[读取配置](/Users/massif/dsh-auracap/client.js:3156)。

**复现：**延迟读取项目上下文；打开设置，在已显示的编辑器输入“还未保存的新草稿”；随后放行读取响应。编辑器关闭，再点编辑，内容变回“现有项目上下文”，新草稿丢失。

**根因：**`profile` 尚未载入被当成空内容编辑；首次响应到来后，不论用户是否已经修改，都执行 `setNote` 和 `setEditing`。

**收敛方向：**区分“未载入”和“已载入为空”；初始化不能覆盖用户编辑。无需增加一套草稿存储框架。

### R05 重新检查状态仍可能接不回真实任务

位置：[状态初始化与重试](/Users/massif/dsh-auracap/client.js:2392)、[状态重试入口](/Users/massif/dsh-auracap/client.js:2506)。

**复现：**模拟本机保留一个已经不存在的旧任务 ID，同时服务端有另一笔真实的 `CREATED` 恢复任务。重载界面后，旧任务被判为过期，导出按钮重新可用；点击后收到“已有导出或恢复正在进行”。再点“重新检查状态”，依然跟踪旧 ID，未接回实际任务。

**根因：**只有 `!task` 才接纳 `status.active`。过期或完成任务仍是一个非空对象，重试只重复查询，没有调和本机记录与服务端状态。多窗口或任务创建响应丢失后可出现这种状态。

**收敛方向：**定义旧终态任务与当前服务端活动任务的接续规则；“重新检查状态”应真正恢复可操作状态，不能一直提示用户等待一个看不到的任务。

证据：[任务界面](/Users/massif/dsh-auracap/output/ui-full-review-20261111/stale-backup-task.png)、浏览器记录中的 `active-task-reconciliation`。

### R06 合并错误仍会串到另一组

位置：[合并回调](/Users/massif/dsh-auracap/client.js:3745)、[分组详情错误参数](/Users/massif/dsh-auracap/client.js:3992)。

**复现：**在组 A 发起重新合并；等待期间切换到组 B；让 A 的请求失败。B 的标题与来源下显示“A 的合并失败”。

**根因：**后续修复为 `groupOperation` 加了操作类型和组 ID，但 `groupError` 仍是全局字符串，失败回调无条件写入，详情无条件展示。进度已归属到目标组，错误还没有。

**收敛方向：**同一次操作的进度、结果、错误和当前展示使用一致的操作身份；切换对象不会把旧错误贴给新对象。

证据：[错误串组截图](/Users/massif/dsh-auracap/output/ui-full-review-20261111/wrong-group-error.png)。这是旧缺陷，最近的两处修复没有新引入它，也没有把这一语义完全收敛。

### R07 洞察状态读取失败，会挡住空库欢迎页

位置：[洞察状态读取](/Users/massif/dsh-auracap/client.js:3311)、[首次进入条件](/Users/massif/dsh-auracap/client.js:3924)、[载入画面](/Users/massif/dsh-auracap/client.js:3944)。

**复现：**条目列表成功返回空库，洞察状态接口返回失败。当前代码一直显示“正在载入内容…”，没有欢迎页的“从电脑导入”和直接恢复入口。同样接口条件下，改版前快照能显示引导页。当前仍可通过头部图标导入、通过设置恢复，并非所有入口都失效。

**收敛方向：**保留“不要把独立洞察误当空库”的判断，但明确区分读取中、成功、失败。失败应有可识别的页面状态、直接重试，以及可用的本地操作，不能用一直载入代替失败。

1. 设置内点击保存后按钮临时禁用，浏览器焦点落到 `BODY`；失败后不会回到设置，按 Escape 无法关闭设置。新键盘监听只挂在面板上，焦点离开后不能接收或约束按键。
2. 卡片分组弹窗没有 dialog 语义与焦点限制，打开后按 `/` 会在它上面再打开主页搜索。普通片刻弹窗、实体弹窗和合并选择也没有采用本次设置的完整键盘规则。

**收敛方向：**复用少量明确的弹窗焦点规则，在控件移除或禁用后维持顶层窗口焦点；共享弹窗的快捷键和语义保持一致。不要为此重写通用弹窗框架。

证据：浏览器记录 `settings-focus-after-save`、`modal-keyboard`，及[叠出搜索截图](/Users/massif/dsh-auracap/output/ui-full-review-20261111/search-over-group.png)。前者是本次新焦点能力的实现缺口；后者属于既有缺陷和本次验收遗漏。

### R09 重新下载和重载会让步骤倒退

位置：[引导阶段推导](/Users/massif/dsh-auracap/client.js:2846)、[下载动作](/Users/massif/dsh-auracap/client.js:3515)。

等待图片时点“重新下载”，下载动作先清空 `shortcutFileMessage`，阶段立即回到安装页；刷新后同样回到安装页。下载失败时还会失去原来的等待语境。

**根因：**是否曾发起下载，与本次下载的临时提示共用一个字段。步骤状态和请求状态不是同一件事。

**收敛方向：**保留已发起下载的事实，重新下载只更新当前请求状态与就近提示；是否跨重载保留可以沿用简洁的引导记录，但不能据此声称手机已经安装。

该行为在改版前已存在，不列为新增回归。

### R10 “合并”“拆分”“取消”没有对应同一套实际语义

位置：[合并选择按钮](/Users/massif/dsh-auracap/client.js:1719)、[手动归组](/Users/massif/dsh-auracap/index.js:3652)、[撤去合并结果](/Users/massif/dsh-auracap/index.js:3154)、[手动归组完成回调](/Users/massif/dsh-auracap/client.js:3810)。

- 选择片刻后的“合并”只创建一个 `candidate` 组，`merged` 仍为空，之后还要点“合并为一篇”才生成合并整理。按钮写“合并 1”还只计算新增选择的一条，实际操作包含当前条目，共两条。
- “拆分”只清除合并整理，来源仍归在同一组；要让片刻真正分开，还需再点“拆开这组”。它和用户理解的直接拆开不是同一个结果。
- 手动归组已提交后，“取消”和关闭仍然只是隐藏窗口。完成回调会继续创建结果并打开分组，不会取消已经提交的动作。

**收敛方向：**明确区分“归为一组”“合并整理”“撤销合并整理”“拆开这组”；进行中的动作如果只能关闭窗口，就不要继续叫取消。具体最终措辞应一次确定，中英文及状态用词一起调整，不用逐个加提示掩盖语义差异。

### R11 英文错误既可能没有下一步，也可能变回中文

位置：[错误翻译](/Users/massif/dsh-auracap/client.js:1146)、[备份错误展示](/Users/massif/dsh-auracap/client.js:2510)。

备份新增错误大多未进入 `ERROR_EN`。请求层遇到中文原因，会退成通用的 “Something went wrong. Please try again.”；轮询到的 `task.error` 又直接展示，不经过相同翻译。因此英文界面可能把“需要重启”“已有连接未结束”“不是完整备份”等不同情况混成重试，或者直接显示中文。

**收敛方向：**利用已有错误 code 对应明确的用户动作，并让同步请求与任务终态使用同一套呈现；具体路径和底层错误可作为诊断信息，不替代用户说明。无需增加更多兜底分支。

### R12 失效连接与“长期有效”提示可能同时出现

位置：[设置连接提示](/Users/massif/dsh-auracap/client.js:2792)、[长期授权文案条件](/Users/massif/dsh-auracap/client.js:2803)。

长期授权被撤销或失效时，状态可以是 `connected + needsReconnect`，同时没有 `tokenExpiresAt`。当前代码一面要求“重新连接 GitHub”，一面又显示“授权长期有效，不需要定期重新登录”。

**收敛方向：**先表达这次连接的实际可用状态；只有授权健康时才显示长期授权说明。“无固定到期日”和“当前仍有效”需要分开。

该条件在改版前也存在。截图中的冲突使用模拟状态，不代表真实账号刚刚过期。
