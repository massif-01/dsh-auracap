## 2. N01–N11 的修改与原因

### N01 合并组成员变化后，旧合并内容仍在

- 修改：`rebuildGroups()` 发现保留组的成员集合变化时，清空 `merged`、把状态退回 `candidate`、必要时顺延 `primaryId`。
- 原因：合并正文是模型对旧成员集合的整体生成结果，无法可靠地局部删除某一段；直接作废、让用户重新合并，比保留一段半截内容更诚实。
- 验证：三屏合并组删一屏后，组仍存在（≥2 屏），合并内容为空，洞察退回逐屏。

### N02 上层洞察的传递来源与字符截断

- 修改：
  - `sourceInsightBlocks()` 返回带 `type:key`、正文和来源 ID 的块；
  - `periodMaterial()` 按 30000 字预算增量拼接，记录真正进入材料的原始片段和已有洞察；
  - 存储 `itemCount`（去重后的原始来源数）、`directItemCount`（直接进入材料的片段数）、`sourceCount`、`sourceItemIds`、`sourceInsightKeys`；
  - `generatePeriodInsight()` 的存在性守卫改为 `directCount || sourceInsightKeys.length`；
  - 界面显示“基于 N 条片刻 · 参考 M 条洞察”，Agent 的洞察工具同步。
- 原因：之前只记录“最近 N 条原始片段”，被日报带进周报的早期条目没有血缘；并且材料截断后来源列表仍按截断前计算。两者都会让“删除”和“来源说明”失真。
- 验证：早期条目经日报进入周报后删除 → 日报和周报都移除；预算被已有洞察占满时，直接片段数为 0、来源只剩实际引用的洞察。

### N03 生成期间删除来源仍会写回

- 修改：在日报、周期洞察、合并三个提交点做“开始前存在的来源，提交时仍存在”的校验；不通过时抛 409，不写盘。
  - 日报：生成开始时保存原始来源快照（`digest.itemIds`，合并组已展开为成员 ID）；
  - 周期洞察：保存 `material.itemIds` 中开始时就存在的子集；
  - 合并：保存成员快照，提交前重新读取 `groupStore` 里的组并比对集合。
- 原因：异步生成跨越删除操作时，不能把已删内容重新写回。校验只针对“生成期间消失”的来源，历史遗留的缺失来源不应阻塞新生成（见 `73fd9a9`）。
- 验证：生成中删除来源返回 409 且不写文件；合并组投影不会被误判（不直接检查 `group:g`）。

### N04 候选组非主屏搜不到

- 修改：`searchGroupsFor()` 未合并组检索所有成员；跨成员的多词查询有回退；结果仍指向组。`e644b3a` 进一步让合并组也检索“合并摘要 + 所有成员”。
- 原因：自动归组后，第二屏的独有内容必须仍然能被搜到；合并摘要可能漏掉细节，所以合并组也要看成员。
- 验证：候选组第二屏的独有关键词命中组；合并后同一关键词仍命中。

### N05 Agent 找不到条目 ID、也读不到内容

- 修改：搜索/线索/相关结果带 ID 和 120 字片段；新增只读 `auracap_moment` 按 ID 返回核心内容（4000 字上限）、标签、线索；组搜索结果附带最多 5 个成员 ID；工具描述和系统提示说明“只在用户问起具体记录时读全文”。
- 原因：工具描述原本声称返回摘要，实际只给标题；不带 ID 也使 `auracap_related` 无法衔接。读取正文是用户明确同意增加的能力，仍受“允许 Agent 读取 AuraCap 记忆”总开关约束。
- 验证：搜索结果包含 ID 和片段；`auracap_moment` 返回正文；组结果成员 ID 可继续读取。

### N06 重新生成返回缓存

- 修改：客户端周期洞察 POST 加 `force: true`。
- 原因：按钮语义就是“重新生成”，服务端已支持 force，前端没传。
- 验证：已有周洞察时重新生成会真正调用模型并更新时间。

### N07 切换周期后迟到响应覆盖当前内容

- 修改：视图请求序号 `insightSeq` 与生成任务 `generationId` 分离：
  - 结果提交同时匹配序号和周期/日期；
  - 切换视图先递增序号，作废在途结果；
  - 生成期间暂停 60 秒定时读取；
  - 生成结束按 `generationId` 决定谁清 busy（即使视图已切走），先清 ref，再按最新视图加载；
  - 客户端 6 分钟超时退出 busy。
- 原因：只用序号会让“切视图时跳过读取”失去失效能力；只用 busy 会导致视图切走后永远停在“正在归纳”。两个所有权必须分开。
- 验证：日报请求晚于周报返回时正文仍是周报；生成期间切换周期不串内容、生成状态正常结束、切换后的周期立即加载。

### N08 授权生命周期在初始请求、轮询异常、初始化交错处未闭环

- 修改：
  - 发出 `/device/code` 之前捕获 `generation`，返回后若已断开则抛 409，不登记流程；
  - `provisionGithub()` 增加 `isCurrent` 回调，在发布 `state.github` 之前检查；
  - 轮询请求异常 → flow 失败并给出可重试提示；
  - 外层 catch 兜底标记失败；
  - `/api/github/device` 路由传递 `error.status`；
  - 删除不可靠的 `connectedAt` 归属判断和事后清理。
- 原因：`connectedAt` 是在共享状态被修改之后才读取的，无法证明“这份状态属于当前流程”；A 初始化中 → 断开 → B 成功 → A 恢复时，A 会把 B 的连接清掉。发布前检查从根上避免旧流程发布状态。
- 验证：初始请求途中断开返回 409 不重连；轮询网络错误进入失败态；A/B 交错后 B 的连接和凭据保持不变。

### N09 重启后 summarizing 永远停在整理中

- 修改：`apply()` 读取 items 后，把所有 `summarizing` 标为 `failed`，错误写“生成被中断，请重试”。
- 原因：进程已经死了，没有任务会完成；不自动重跑模型，避免重启时产生未预期费用，详情页已有手动重试。
- 验证：预置 summarizing 记录，启动后变 failed。

### N10 同步超过三分钟允许重入

- 修改：去掉“3 分钟后允许第二次同步”，改为严格单飞；保留 `syncingSince`，超过 5 分钟由 watchdog 暴露 `syncingForMs` 并写提示，但不自动重入。
- 原因：重入会造成重复导入；网络请求已有超时，真正卡死时提示用户重启，比静默重入安全。
- 验证：慢同步期间第二次同步立即返回，只导入一条。

### N11 实体搜索结果只显示“线索”

- 修改：搜索结果标题回退到 `result.name`，实体结果用出现次数作为副标题。
- 原因：字段契约不一致，实体结果没有 `title`。
- 验证：实体结果行显示实体名和次数。

## 3. 两条后续修改

- `64e24a8`：洞察生成请求加 6 分钟客户端超时；超时显示“生成超时，请重试”，保证 busy 不会永久卡住。
- `73fd9a9`：把“开始前已缺失”和“生成期间被删除”分开；只校验开始时就存在的来源，并在落盘时过滤已失效 ID。原因：旧洞察引用早已删除的条目时，原实现会让周/月/年洞察永久 409。

## 5. 已知边界（本次未修）

1. 客户端 N06/N07/N11 和超时没有自动化浏览器测试，需要人工验收；
2. 插件重载时，旧上下文里正在跑的总结可能在稍后把旧数组写回，覆盖 N09 的“已中断”标记（既有重载竞态，概率低）；
3. N10 的 watchdog 只提示不自动恢复，真卡死需重启插件（设计取舍）；
4. 旧洞察的传递来源缺失不追溯，只保证新生成的结果不再被阻塞；
5. `digestLoaded` 是未被读取的状态（既有代码，未动）。
