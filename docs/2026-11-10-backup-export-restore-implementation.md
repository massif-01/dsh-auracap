# 备份、导出与恢复：实施与验证

基于已确认的 V2 方案及静态预览实施，日期：2026-11-10。当前为本地代码变更，未提交、发布或替换正在使用的插件。

## 已实现

- 设置页增加「备份与导出」，沿用正式版单列布局、灰色小标题和已确认的预览样式。
- 导出菜单支持完整 `.auracap.zip`、仅图片 ZIP、仅文本 Markdown ZIP。
- 完整包保存当前可用图片、条目全文、已有总结、分组合并结果、日洞察、周迹、月迹、岁迹及项目上下文。图片优先读取本地副本；没有副本时使用 Harness 保存的版本，不要求最初上传的图片。
- 不打包原始 PDF、用量记录、密钥、GitHub 授权和设备运行状态。PDF 已提取文字及已有总结保留。
- 恢复先展示文件、时间及内容数量，确认后完整替换内容库；不合并、不去重、不重新调用模型。保留当前设备连接与权限设置，用量清零。
- 恢复重建宿主附件引用及本地索引。恢复后的定时任务通过内容基线判断新材料，防止旧内容被启动任务重新生成；用户手动重新整理仍可使用。
- 导出、恢复共用任务状态和内容操作边界；恢复切换等待已接纳的写任务完成，切换后旧页面及旧任务不能覆盖新库。
- 恢复事务在磁盘记录提交决定。切换前失败返回原库，提交后中断在下次启动完成载入。恢复窗口、文件选择、进度、取消、过期和重查状态接入真实接口。

## 代码位置

| 文件 | 职责 |

| `backup/tasks.js` | 任务、上传下载、确认与取消、临时文件生命周期 |
| `backup/restore.js` | 准备新库、目录切换、提交及启动恢复 |
| `backup/runtime.js` | 内容任务边界、库代次、恢复内容基线 |
| `backup/io.js` | 持久化文件操作、分块哈希 |

| `client.js` | 设置入口、菜单、恢复弹窗与状态展示 |

没有引入第二套内容存储或云端服务。README、依赖锁及第三方许可已同步。

## 验证结果

1. `node --experimental-vm-modules scripts/test-backup.mjs`：6 组通过。覆盖跨设备完整恢复、三种导出、损坏输入、后台写入等待、目录切换故障，以及真实 SIGKILL 和回滚再次中断。检查恢复及重启没有模型调用、旧请求被拒绝、重复确认不覆盖后续修改、手动重试仍有效。
2. `node --experimental-vm-modules scripts/test-performance.mjs`：既有 8 组回归通过，分组、轻量列表、游标与 PDF 解析行为保持。
3. `node scripts/test-insight-parser.mjs`、JavaScript 语法检查、`git diff --check` 通过。另核对流式指纹与完整字符串对中文、emoji、转义和跨块字符的结果一致。
4. 浏览器使用正式 `client.js` 和真实备份 API：导出下载、文件选择、检查、确认及恢复完成已走通；检查 390px 窄窗口、菜单键盘操作、焦点和溢出。最后复查发现失效任务会锁住窗口，已改为明确过期状态并允许重新选择；查询失败提供手动重查状态入口。
5. 使用已安装 Harness 的 Node 24.21.0 和附件组件，在临时目录完成图片打包、跨附件库恢复与读取。只剩宿主处理版本的图片能够正常恢复，已有总结原样保留。
6. 最终 npm 包在独立消费目录安装并通过 Harness Node 运行，备份 API 返回 200；包含全部 `backup/*.js`、依赖及许可，无开发源码路径依赖。

### 容量实测

通过正式 HTTP 接口完成大包导出、上传、检查及恢复；大文件传输客户端使用独立 curl 进程，测试数据运行后清理。

| 项目 | 实测值 |
| --- | --- |
| 洞察文件 | 34 份 |
| 文本正文总字节 | 2,142,000,000，接近 2 GiB 解压上限 |
| ZIP 大小 | 1,622,512,902 字节 |
| 模型调用 | 0 |
| 导出至恢复完成耗时 | 约 93 秒 |
| 插件处理阶段采样最高 RSS | 406,880,256 字节，约 388 MiB |
| 含测试端最终全文断言的最高 RSS | 596,557,824 字节，约 569 MiB |

这是接近 **解压内容上限** 的实测，不代表测试过 2 GiB 的 ZIP 文件。大洞察的内容指纹使用流式解析，事务文件校验使用固定缓冲区，避免恢复时集中载入整个包。当前限制为 ZIP 和解压总量各 2 GiB、50,000 个文件、单 JSON/Markdown 64 MiB、单图片 40 MiB。
